# kafka-rest-client

PHP-клиент для [Confluent REST Proxy](https://docs.confluent.io/platform/current/kafka-rest/index.html). Библиотека позволяет отправлять JSON-сообщения в Apache Kafka и получать их через HTTP-интерфейс REST Proxy.

## Требования

- PHP 8.2 или новее;
- расширение PHP `curl`;
- доступный экземпляр Confluent REST Proxy;
- Composer.

## Установка

Пакет называется `adsniper/kafka-rest-client`. В репозитории пока нет тегов релизов, поэтому используется ветка `dev-main`.

### Ручная настройка

Добавьте в `composer.json` проекта VCS-репозиторий и зависимость. Если поля `repositories` или `require` уже есть, дополните их указанными значениями.

```json
{
    "repositories": [
        {
            "type": "vcs",
            "url": "https://github.com/adsniper/kafka-rest-client"
        }
    ],
    "require": {
        "adsniper/kafka-rest-client": "dev-main"
    }
}
```

После этого выполните обновление зависимостей Composer.

### Установка через Composer

Добавьте репозиторий и установите пакет следующими командами:

```bash
composer config repositories.kafka-rest-client vcs https://github.com/adsniper/kafka-rest-client
composer require adsniper/kafka-rest-client:dev-main
```

## Основные компоненты

| Компонент | Назначение |
| --- | --- |
| `QueueRestClient` | Выполняет HTTP-запросы к REST Proxy на базе переданного Guzzle-клиента. Поддерживает PSR-3 логгер. |
| `QueueRestProducer` | Отправляет массивы данных в заданный Kafka-топик. |
| `QueueRestConsumer` | Создаёт экземпляр consumer, подписывает его на топик, получает сообщения и фиксирует смещения после успешной обработки. |
| `QueueMessageHandlerInterface` | Контракт обработчика сообщений потребителя. Метод `handle` получает ключ и данные сообщения и возвращает результат обработки. |

`QueueRestClient` получает Guzzle-клиент и конфигурацию при создании. Параметр `host` задаёт базовый адрес REST Proxy. Для диагностики можно передать PSR-3 логгер через `setLogger`.

## Конфигурация

Параметры передаются в `setConfig` производителя или потребителя. Повторный вызов дополняет текущую конфигурацию.

### Параметры клиента

| Параметр | Обязателен | Описание |
| --- | --- | --- |
| `host` | Да, кроме режима разработки | Базовый адрес Confluent REST Proxy. |
| `dev` | Нет | При значении `true` и пустом `host` запросы не выполняются; клиент возвращает пустой JSON-объект. По умолчанию `false`. |

### Параметры производителя

| Параметр | Обязателен | Описание |
| --- | --- | --- |
| `topic` | Да | Kafka-топик для отправки сообщений. |

Сообщение передаётся как массив и сериализуется в JSON. Ключ сообщения необязателен.

### Параметры потребителя

| Параметр | Обязателен | Описание |
| --- | --- | --- |
| `topic` | Да | Kafka-топик, на который подписывается consumer. |
| `group` | Да | Идентификатор группы потребителей. |
| `consumerInstance` | Да | Имя экземпляра consumer в REST Proxy. |
| `auto.offset.reset` | Нет | Начальная позиция чтения при отсутствии сохранённого смещения. По умолчанию `earliest`. |
| `enable.auto.commit` | Нет | Автоматическое подтверждение смещений. По умолчанию `false`. |
| `timeout` | Нет | Максимальная продолжительность работы потребителя в секундах. По умолчанию 60. |

Перед запуском потребителя необходимо задать обработчик, реализующий `QueueMessageHandlerInterface`. Смещение каждого сообщения фиксируется, только если обработчик возвращает `true`. При завершении работы вызовите `close`, чтобы удалить экземпляр consumer из REST Proxy.

## Ошибки и журналирование

Ошибки обязательной конфигурации выбрасываются как `QueueException`; коды доступны в `QueueExceptionCodes`. Ошибочные ответы REST Proxy преобразуются в исключения Guzzle `RequestException`. Для записи HTTP-запросов и исключений подключите совместимый с PSR-3 логгер методом `QueueRestClient::setLogger`.
